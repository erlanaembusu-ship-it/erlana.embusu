# FastBid GosZakup

Кроссплатформенное (Windows 10/11, macOS) десктоп-приложение для **скоростной
автоматизированной подачи заявок** на портал госзакупок РК
(`goszakup.gov.kz`). Заявка уходит в момент открытия окна (T0), «горячая»
часть после T0 ограничена жёстким бюджетом **5 с** (см. §1.1).

Python 3.13 (нужна сборка с Tcl/Tk для GUI), асинхронный стек (`asyncio`,
`httpx[http2]`, `websockets`, `cryptography`) + GUI на `customtkinter`.

---

## 1. Как это работает (ключевая идея)

В момент открытия окна приёма заявок (T0) выполняется **только один сетевой
вызов — финальный submit**. Всё остальное делается заранее, параллельно с
ожиданием T0:

```
 clock → plan → ┌── warmup (подпись + предзагрузка документов) ──┐
                └── watch (адаптивный поллер, таймер T0) ────────┘ → submit → verify
```

| Этап | Что происходит | Типичное время |
|------|----------------|----------------|
| `clock` | синхронизация часов с сервером по `Date`-заголовкам (+ фоновое уточнение до ±RTT/2) | ~160 мс |
| `plan`  | сборка payload из нишевого шаблона и данных лота | ~40 мс |
| `warmup`| **пакетная подпись всех документов одним вызовом NCALayer** + предзагрузка вложений | ~20 мс + сеть |
| `wait`  | ожидание `TrdBuy.startDate` (T0) | до T0 |
| `submit`| POST заявки с ключом идемпотентности; повторы на 425/сбоях — в бюджете 5 с | 2–7 мс + RTT |
| `verify`| подтверждение факта подачи | 0–2 мс |

T0 берётся из данных портала: приём заявок открывается в
`TrdBuy.startDate`. `repeatStartDate` — срок начала ДОПОЛНЕНИЯ заявок
повторных закупок, его использование как T0 приводило к пропуску окна
подачи. Подтверждено официальной схемой GraphQL API v3.

### 1.1. Гарантия «5 секунд» после T0

* **Часы.** `Date` имеет разрешение 1 с, поэтому каждая выборка задаёт
  интервал смещения; интервалы пересекаются, а фоновые зонды на смене
  секунды (`LotWatcher.refine_clock`, если до T0 > 2 с) сужают погрешность
  до ±RTT/2. Раньше точечная оценка запаздывала до 1 с.
* **Выстрел.** Таймер T0 прерывает сон и опрос реестра: медленный или
  «зависший» OWS больше не задерживает submit. Лимит наблюдения
  (`max_watch_seconds`) при известном T0 продлевается до T0 — взвод с вечера
  не истекает ночью.
* **Submit.** `RetryPolicy.submit_budget_s = 5.0`: все POST, повторы на
  `425/408/429/5xx`/обрыв сети (тот же idem-ключ) и verify перед повтором
  укладываются в 5 с от первого POST. Каждый запрос — одна попытка без
  relogin, таймаут подрезается до остатка бюджета. После 425 повтор идёт
  сразу (заявка точно не создана); после неоднозначного сбоя — сначала
  verify по ключу. Если бюджет исчерпан на неоднозначном исходе, выполняется
  финальная проверка по ключу, чтобы не сообщить ложный отказ.
* **Проверка.** `--selftest` меряет `t0_to_accept_ms` по часам самого mock-
  портала и падает, если заявка принята позже бюджета. Реалистичная сеть:
  `--latency-ms 80`.

Бюджет не покрывает подготовку до T0: подпись в диалоге NCALayer (выбор
ключа, PIN) — действие пользователя, поэтому заявку нужно взвести заранее.

## 3. Запуск

```bash
pip install -r requirements.txt       # только запуск
pip install -r requirements-dev.txt   # запуск + тесты, ruff, сборка EXE

python main.py                      # LIVE: чтение реестра, подача заблокирована (см. §5)
python main.py --mock --open-after 20   # демонстрация на локальных заглушках
python main.py --selftest --open-after 6  # headless-самопроверка (для CI)
python main.py --selftest --open-after 6 --latency-ms 80  # то же с RTT ~80 мс
pytest tests/ -q                    # 151 тест
```

`--selftest` печатает отчёт: стадии, `t0_delta_ms`, `t0_to_accept_ms`
(по часам портала), погрешность часов, счётчики портала/NCALayer.

### Сборка GUI-исполняемого файла (.exe)

```bash
pip install -r requirements-dev.txt
build_exe.bat        # или: pyinstaller fastbid.spec --noconfirm
```

Результат — **`dist\FastBid.exe`** (~20 МБ, onefile, windowed): автономный
GUI без установленного Python. Пользовательские данные и журнал лежат в
`%APPDATA%\FastBidGosZakup\`. Отладочная сборка с консольным окном:

```bat
set FASTBID_CONSOLE=1
pyinstaller fastbid.spec --noconfirm
```

На macOS сборка аналогична: `pyinstaller fastbid.spec` (получится
`dist/FastBid.app`; для запуска на «чужих» машинах собирайте на самой macOS).

## 4. NCALayer и ЭЦП

* Подключение: `wss://127.0.0.1:13579/kz.gov.pki.knca.basics` (модуль
  `kz.gov.pki.knca.basics`, резерв — `/kz.gov.pki.knca`; схема по умолчанию
  wss, ws — только для mock-сервера). Доверие к самоподписанному сертификату
  допустимо только для loopback-хостов: попытка wss-подключения к любому
  другому хосту отклоняется (`NCA_NOT_LOOPBACK`).
* Конверт: `{"module": "...", "method": "sign", "args": {...}}`.
* **Пакетная подпись**: `args.data` принимает МАССИВ base64-документов — вся
  пачка подписывается **одной операцией**, то есть одним системным диалогом
  вместо диалога на каждый файл (возможность модуля `basics`, осень 2024).
  Для старых версий NCALayer есть автоматический fallback на поштучную подпись.
* Ответ: `{"status": true, "body": {"result": ...}}`; `body` без `result` —
  пользователь отменил операцию; ошибка — `{"status": false, ...}`.
* **Пароль ЭЦП** запрашивает сам NCALayer в системном диалоге (приложение
  пароль не спрашивает и не хранит); внутреннее представление в памяти —
  `SecretPassword` на `bytearray` с затиранием нулями, никогда не пишется
  на диск и не попадает в логи.
  ВАЖНО: НУЦ РК не документирует передачу пароля в методе `sign`; подавление
  диалогов «на каждый файл» обеспечивает сам пакетный вызов. Проброс пароля
  в payload включён по умолчанию (`ncalayer.pass_password = True` — для
  сборок, которые его поддерживают, и для mock-тестов).
* БИН/ИИН извлекается из сертификата, встроенного в CMS-подпись
  (`serialNumber` и OID ветки `1.2.398.3.3.4`), и используется для привязки
  лицензии и автозаполнения заявки.

### Режим директора (автоподпись)

Для одиночного рабочего места (машина директора): в «Настройки» → «ЭЦП
директора» сохраните алиас ключа и пароль ЭЦП — они шифруются **DPAPI
Windows** (расшифровка только тем же пользователем на той же машине) и
далее подпись выполняется без диалогов NCALayer. Пароль и алиас не
покидают машину и не попадают в репозиторий. Включение режима — осознанное
решение: любой, кто получит сессию Windows директора, сможет подписывать.

## 5. Аутентификация, LIVE-режим и достоверность endpoint'ов

### Что работает в LIVE (реальный портал)

* **Чтение реестра OWS v3** (`https://ows.goszakup.gov.kz/v3/graphql`):
  поиск и отслеживание лотов, T0, синхронизация часов (по заголовку `Date`
  ответа реестра).
* **Доступ к реестру OWS.** Реестр отвечает `HTTP 401` организациям без
  доступа к унифицированным сервисам. Доступ выпускается по запросу в
  АО «Центр электронных финансов» (`support@ecc.kz`); после выпуска токен
  виден в кабинете (`v3bl.goszakup.gov.kz/ru/org_profile/ows_token`).
  При 401 приложение выводит объяснение с кодом `OWS_UNAUTHORIZED`.
* **DRY-RUN**: сборка и проверка плана заявки без подписи, загрузок и подачи.

### Что заблокировано в LIVE и почему

Единая платформа закупок — закрытый SPA; публичного API входа и подачи для
сторонних клиентов нет, а пути кабинета в `config/settings.py` помечены
`VERIFY:` (не сверены с реальным трафиком). Пока контракт не подтверждён,
приложение **не входит в кабинет и не подаёт заявки**:

| Уровень | Что делает |
|---|---|
| Настройки | `AppSettings.cabinet_api_verified` / `live_submit_allowed` = `False` вне локального mock |
| Ядро | `BidPipeline._live_guard` в `warmup`/`submit`, стоп в `run_cycle` до подписи и наблюдения (`LIVE_SUBMIT_UNVERIFIED`) — независимо от UI |
| Сессия | прямой ЭЦП-вход в API, ping, keep-alive и relogin кабинета отключены (`LIVE_AUTH_UNVERIFIED`); сессия берётся из браузера и проверяется GET-запросом страницы кабинета |
| UI | DRY-RUN принудительно включён и не снимается |

### Вход в LIVE

* **«Войти по ЭЦП»** — FastBid открывает Edge/Chrome/Chromium с **отдельным
  профилем** (`%APPDATA%\FastBidGosZakup\browser_profile`) на официальном
  входе (`https://v3bl.goszakup.gov.kz/ru/user/sso_redirect`). Входите по
  ЭЦП/NCALayer как обычно — после входа FastBid сам забирает Cookie кабинета
  через DevTools-протокол (только `127.0.0.1`), проверяет их страницей
  кабинета и сохраняет DPAPI. «Заблокировать» во время ожидания отменяет вход.
  Путь к браузеру можно задать `FASTBID_BROWSER`, таймаут —
  `FASTBID_BROWSER_LOGIN_TIMEOUT` (по умолчанию 600 с). Выход из кабинета в
  этом окне браузера завершает и сессию FastBid (Cookie общие).
* **«Войти по токену»** — ручная вставка Cookie из DevTools любого браузера.
  Проверочная страница — `FASTBID_CABINET_CHECK_PATH` (по умолчанию
  `/ru/cabinet/profile`, `VERIFY`).
* Кнопка «Открыть портал в браузере» просто открывает портал в браузере по
  умолчанию — такой вход FastBid **не** видит.

**Единственная точка разблокировки** — свойство
`AppSettings.cabinet_api_verified` в `config/settings.py`. Менять его можно
только после сверки путей и формата кабинета по HAR-записи реальной подачи.

### Вход на mock-портале

* **token**: «Войти по токену» → вставить `Authorization` (с `Bearer`),
  `Cookie` или сам токен — парсер принимает любой формат; токен живёт в RAM.
* **ecp**: «Войти по ЭЦП» → NCALayer сам показывает выбор ключа и запрашивает
  пароль; БИН/ИИН и ФИО читаются из сертификата, подписывается challenge.

### Endpoint'ы

* Публичный реестр OWS v3 (`https://ows.goszakup.gov.kz/v3/graphql`) — поля
  `Lots`, `TrdBuy`, `LotsFiltersInput` сверены с официальной схемой:
  <https://ows.goszakup.gov.kz/help/v3/schema/query.doc.html>.
* Публичный OWS работает **только на чтение**; подача заявки — действие
  личного кабинета. Пути кабинета в `config/settings.py` помечены `VERIFY:`.
* Для автономной разработки все пути обслуживает mock-сервер
  (`python main.py --mock`), где работают и ЭЦП-вход, и токен-вход.

## 6. Лицензирование

* Лицензия — JSON, подписанный **Ed25519**-ключом вендора. Публичный ключ
  вендора **вшит в код** (`core/vendor_key.py`) — единственный доверенный
  источник: env-подмен и файлов ключа нет, самовыпуск лицензии из
  публичного репозитория исключён. Приватный ключ вендора хранится ВНЕ
  репозитория и поставки.
* Привязка: БИН/ИИН (из ЭЦП) + HWID. HWID нормализуется на выпуске и при
  проверке (формат с дефисами и «сырой» эквивалентны).
* Триал 14 дней (день старта — полный день), офлайн-грейс, строгая проверка
  привязки после входа по ЭЦП. Старт триала дублируется (реестр Windows /
  домашний файл): удаление или подделка одного из источников триал не
  сбрасывает и не продлевает (берётся РАННЯЯ дата, старт «в будущем» —
  недействителен). Отметка последнего запуска там же: перевод часов назад
  больше чем на 1 ч делает лицензию/триал недействительными.
* Выпуск: БИН/ИИН — ровно 12 цифр, срок > 0; лицензия без БИН при
  проверке отклоняется.

```bash
python main.py --gen-keys      # пара ключей вендора (public → core/vendor_key.py)
python main.py --hwid          # HWID клиента
python main.py --issue-license --private-key vendor.pem \
    --bin 123456789012 --target-hwid <HWID> --licensee "ТОО ..." --days 365
```

Блокировка при недействительной лицензии: `FASTBID_LICENSE_ENFORCE=1`
(по умолчанию приложение работает и предупреждает). Если переменная задана
при сборке (`pyinstaller fastbid.spec`), спека вшивает её в EXE через
runtime-hook.

## 7. Тесты

`py -3.13 -m pytest tests/ -q` → **151 passed** (Python 3.13.11, Linux +
xvfb; 8 тестовых файлов): CMS-криптография и извлечение БИН,
пакетная подпись (1 вызов = 1 диалог), fallback на старый NCALayer, отмена
пользователем, проброс пароля, полный цикл с таймингами, отказ до T0
(HTTP 425), идемпотентность повторной подачи, auto-relogin по 401, лицензии
(выпуск/подделка/истечение/привязка), ниши, парсинг дат, синхронизация часов,
регрессии UI/фонового моста, ссылка на карточку через кабинет и mock,
отсутствие connection-specific заголовков в `default_headers()` и ASCII-кодировка
`build_exe.bat`; защита LIVE-режима (ядро и UI отказывают в реальной подаче
без подтверждённого API, сессия не обращается к кабинету, запросов к реестру без токена нет
только в реестр, 401 объясняется, wss NCALayer — только loopback, первая
проверка открытия выполняется сразу после T0). При отсутствии Tcl/Tk часть
UI-проверок пропускается.

Регрессии аудита: `test_submit_budget.py` (часы, выстрел по T0 при
«зависшем» реестре, 425-повторы, потерянный ответ submit, бюджет 5 с),
`test_ncalayer_audit.py` (опоздавшее приветствие, обрыв сокета, неверный
PIN без повторов, БИН из сертификата ТОО, `::1`), `test_license_audit.py`
(подделка триала, перевод часов, выпуск), `test_audit_misc.py` (ниши,
автоцена, журнал). Резерв триала в тестах подменяется в памяти
(`tests/conftest.py`) — реестр и `$HOME` не трогаются.

Если `TEMP`/`TMP` указывают на каталог без прав записи (pytest падает с
`PermissionError` на `pytest-of-<user>`), задайте каталог явно:
`pytest tests/ -q --basetemp %LOCALAPPDATA%\Temp\fastbid-pytest`.

Дополнительные проверки:

```bash
py -3.13 -m ruff check .
py -3.13 -m ruff check --select UP041 .
```

работоспособность непроверенных LIVE-endpoint'ов и не пересобирают EXE.
