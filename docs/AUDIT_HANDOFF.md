## P1 — доработки для полного автомата

1. **TumarCSP не интегрирован** (единственное человеческое звено подготовки).
   Нужно: CryptoSocket API — `SYSAPI.SetAPIKey` (`apiKey` = `hsm_api_key`
   из inline-скрипта страницы) → `BaseAPI.GetVersion {type:3}` →
   `EFCAPI.EncryptOfferPrice` (плановая и демпинговая суммы, `id_priceoffer`,
   `public_key`, `salt`, `sign`; шифртекст → `ajax_add_encrypt`). Портал
   получает только шифртекст — цена нигде не хранится открыто.
2. **Авто-восстановление сессии при истечении.** Сейчас при истечении
   ci_session (живёт ~10 мин) восстановление идёт только из DPAPI-снимка;
   если он отозван — ручной вход. Рабочий механизм уже написан: захват
   cookie из `browser_profile` через CDP + `sso_redirect` (SSO-cookie живёт
   дольше, выдаёт свежий ci_session без ЭЦП) — см. gitignored скрипт
   `C:/GOZAKUP3/probe_cabinet_live.py` (функция `capture_session`, ~7 с).
   Перенести в `core/session_manager.py`/`ui/app.py`: при TOKEN_REJECTED на
   старте — пробовать recapture перед запросом ручного входа.
3. **Создание заявки → документы → квалификация** (шаги до ценовых
   предложений) не автоматизированы и в HAR-записи ОТСУТСТВУЮТ — нужен HAR
   этих шагов с реальной заявки (DevTools → Network). Автопилот сейчас
   умеет: чтение объявления, расчёт цены, пакет документов, взвод готового
   черновика.
4. **«Первые секунды T0» на реальном портале не проверены end-to-end** —
   mock-самотест даёт 83 мс, но живой выстрел ровно в момент открытия приёма
   ещё не случался (обе реальные подачи были в уже открытый приём). Механика
   (часы сервера, draft_prepare_lead_s=45, retry-окно 20 с, тот же csrf)
   покрыта тестами.
5. **UI-путаница старого и нового пути подачи.** Вкладка «Лоты» в LIVE
   принудительно DRY-RUN (старый конвейер `/api/bid/*` — таких путей на
   портале НЕТ, флаг `cabinet_api_verified`=False), а панель «Подача
   подготовленной заявки» на «Панели» — рабочий путь. Баннеры/тексты стоит
   свести к одному сообщению, а мёртвый `/api/bid/*`-конвейер
   (`core/bid_pipeline.py`, endpoints `bid_*`, `auth_*`, `session_ping_path`)
   либо удалить, либо явно пометить как mock-стенд.

## P2 — техдолг и безопасность (из аудитов, отложено)

1. **CMS-верификация подписанта**: берётся первый сертификат, принадлежность
   подписанта не проверяется (containment-чек есть, проверки ИИН/БИН нет).
2. **str-копии пароля ЭЦП**: JSON-протокол NCALayer не позволяет затереть
   строку — пароль живёт в памяти дольше нужного.
3. **Watch >6 ч**: фоновое наблюдение лота отваливается после подписи;
   таймеры при модалках.
4. **Подпись trial.json**: файл триала не подписан (подделываем локально).
5. **Пароль в `signerParams`** (`pass_password=True`): НУЦ не документирует
   приём пароля в sign — сборка NCALayer может игнорировать и показать своё
   окно (одно на пакет). Режим «ноль диалогов» у директора может дать один
   диалог на пакет подписи.
6. **CI**: workflow `.github/workflows/ci.yml` есть; на прошлом аккаунте
   Actions были заблокированы биллингом GitHub. На этом репо включить и
   убедиться, что 182 теста зелёные в CI (1 UI-тест skipped без дисплея —
   в CI с xvfb должен проходить).
7. **OWS-доступ организации не выпущен** (выдаёт ЦЭФ по запросу,
   support@ecc.kz, 8 7172 73 55 15): чтение реестра в LIVE = 401. Токен
   (после выпуска доступа) появится в кабинете: Профиль участника → Токены.
   Без него автопилот по реальным лотам работает только через страницы
   v3bl (v3bl_reader) — это осознанное решение, токен OWS удалён из кода.

## Ограничения (не делать)

- **Капча не обходится**: если портал показывает reCAPTCHA на предпросмотре
  (маркеры: `data-sitekey`, `g-recaptcha`), автоподача запрещена кодом
  (`CAPTCHA_REQUIRED`) — подача вручную. Скрипт reCAPTCHA сам по себе НЕ
  признак капчи (он есть и в успешной подаче).
- **NCALayer wss только loopback** (127.0.0.1) — проверяется кодом.
- Секреты (пароль ЭЦП, cookie сессии) — только DPAPI
  (`%APPDATA%/FastBidGosZakup/`), вне репозитория. Приватный ключ вендора
  лицензий — `C:/GOZAKUP3/vendor/`, вне репозитория. Не переносить их в репо.
- Реальная подача — осознанное действие владельца: галочка «Реальная
  подача» + диалог подтверждения; ядро проверяет `cabinet_pages_verified`
  независимо от UI.
